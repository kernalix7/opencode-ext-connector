# v0.3.3 릴리스 및 인수인계 기록

## 상태 및 범위

`opencode-ext-connector@0.3.3`는 공개되었습니다. 이 기록은 변경 불가능한 npm 패키지, 릴리스 워크플로 복구, 저장소 인수인계를 다루며, 프로바이더 접근 권한을 추가하거나 미공개 프로바이더 프로토콜을 보장하지 않습니다. 프로젝트는 독립적이고 비공식적입니다. BSD-3-Clause는 이 저장소의 소스에만 적용되며, 사용자는 프로바이더 약관과 허용된 접근에 대한 책임을 집니다.

## 사용자 적용 및 호환성 경계

안정적인 OpenCode V1에서는 `opencode.json`에 다음 정확한 항목을 넣으십시오:

```json
{"plugin": ["opencode-ext-connector@0.3.3"]}
```

OpenCode를 완전히 종료한 뒤 다시 시작하고, `/models`로 프로바이더가 표시되는지 확인하십시오. 공개 여부는 여전히 각 프로바이더별 OpenCode 인증 레코드와 사용 가능한 벤더 또는 로컬 자격 증명에 달려 있으며, 설치만으로 프로바이더가 공개되지는 않습니다.

**V2 호환성: 지원하지 않음.** V2는 복수형 `plugins`와 변경된 API를 사용하므로, 이 V1 기록은 V2 지원을 주장하지 않습니다. 참고: [V1 플러그인](https://opencode.ai/docs/plugins/), [V2 플러그인](https://opencode.ai/v2/docs/plugins/), [V1 마이그레이션 플러그인](https://opencode.ai/v2/docs/migrate-v1/#plugins).

## 복구 이력 및 최종 워크플로

[첫 실패 실행 34022281701](https://github.com/kernalix7/opencode-ext-connector/actions/runs/34022281701)에서는 검증과 패키지 준비가 통과했습니다. bare tarball 인수가 GitHub shorthand로 해석되어 publish만 실패했습니다. 복구는 [PR #6](https://github.com/kernalix7/opencode-ext-connector/pull/6)에서 추적했고, 워크플로 정리는 [PR #7](https://github.com/kernalix7/opencode-ext-connector/pull/7)에서 추적했습니다.

영구 publish 명령은 정확히 다음과 같습니다:

```bash
npm publish "./${{ steps.artifact.outputs.tarball }}" --provenance --access public
```

최종 릴리스 워크플로는 `v*` 태그 push 전용이며 `verify`와 `publish` 작업으로 구성됩니다. 임시 dispatch 및 recovery 경로는 제거되었습니다.
