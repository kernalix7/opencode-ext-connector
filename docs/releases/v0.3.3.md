## Status and scope

`opencode-ext-connector@0.3.3` is published. This record covers the immutable npm package, its release-workflow recovery, and the repository handoff; it does not add provider access rights or guarantee unpublished provider protocols. The project remains independent and unofficial. BSD-3-Clause applies to this repository's source only; users remain responsible for provider terms and permitted access.

## User application and compatibility boundary

For stable OpenCode V1, put this exact entry in `opencode.json`:

```json
{"plugin": ["opencode-ext-connector@0.3.3"]}
```

Fully quit and restart OpenCode, then use `/models` to verify provider visibility. Publication still depends on each provider's OpenCode auth record and usable vendor or local credentials; installation alone does not publish a provider.

**V2 compatibility: not supported.** V2 uses plural `plugins` and a changed API, so this V1 record makes no V2 support claim. References: [V1 plugins](https://opencode.ai/docs/plugins/), [V2 plugins](https://opencode.ai/v2/docs/plugins/), and [V1 migration plugins](https://opencode.ai/v2/docs/migrate-v1/#plugins).

## Recovery history and final workflow

The [first failed run 34022281701](https://github.com/kernalix7/opencode-ext-connector/actions/runs/34022281701) passed verification and package preparation. Only publishing failed because the bare tarball argument was interpreted as GitHub shorthand. The recovery was tracked in [PR #6](https://github.com/kernalix7/opencode-ext-connector/pull/6); workflow cleanup was tracked in [PR #7](https://github.com/kernalix7/opencode-ext-connector/pull/7).


The final release workflow is `v*` tag-push only, with `verify` and `publish` jobs. Temporary dispatch and recovery paths were removed.
